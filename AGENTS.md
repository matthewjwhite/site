# Repository Instructions

## Markdown formatting

- For markdown files under `content/blog/`, keep prose in semantic line
  breaks: one sentence or clause per line when practical.
- Keep lines readable with a natural paragraph shape.
- Aim for roughly 100 characters where practical, but do not force a hard
  maximum.
- Prefer grammatical sentence or clause breaks over rigid width.
- Avoid paragraph tails of 1-3 words when a nearby clause break can
  keep the shape natural; allow short tails only when the alternative
  would be much longer or more awkward.
- Preserve front matter formatting as-is unless the user asks for a
  broader cleanup.
- Formatting changes must never alter wording, meaning, punctuation, or
  content. Only Markdown structure and layout may change.
- Do not reflow fenced code blocks or inline code spans.
- Keep list items readable and indented consistently.
- If a post is already using this style, preserve it during future edits.

## General

- Prefer ASCII unless the file already uses a different character set.
- Make the smallest change that satisfies the request.
